## התאמה מתקדמת (תוספת ב100 מהראשי, 16.11)

**מה יש היום בקוד החי:**
- **דף התשלום:** `fbq("init", id, ud)` עם **em ו-ph בלבד**, מ-cc_det: בטעינה, ושוב אחרי שהפרטים מתקבלים. אין fn/ln. האירועים עצמם בלי user data.
- **דף התודה:** `fbq("init", id)` **בלי נתונים בכלל**, ולכן ה-Purchase מהדפדפן יוצא בלי em/ph/fn/ln. ההתאמה מגיעה רק מה-CAPI.

**המלצה (`patch_am.py`, מוכן ונבדק 2/2, לפרוס רק אחרי "מאשר"):**
- **NLP_PIX_UD בדף התשלום:** מוסיף fn ו-ln (המילה הראשונה והאחרונה בשם, באותיות קטנות).
- **דף התודה:** מעביר init עם em, ph, fn ו-ln מ-cc_det. אותו session ואותו דומיין, וכך ה-Purchase מהדפדפן נושא התאמה ידנית.

- **בצד CAPI:** fn, ln ו-external_id ב-7827404 (בממשק, למעלה). ב-8443951 כבר יש.

**מניעת כפילויות:** לא מושפעת. Meta מאחדת לפי event_name ו-event_id (מספר העסקה), לא לפי פרטי המשתמש. פרטים זהים בשני הצדדים רק משפרים את ההתאמה.

**סיכונים:**
- **פרטיות:** נשלחים פרטים אישיים, מגובבים בדפדפן לפני השליחה. מדיניות הפרטיות כבר מכסה מייל וטלפון. שם פרטי ושם משפחה זה תוספת, וכדאי שבן יאשר.
